• ROLLBACK: 
 -------------

• This command helps you undo recent changes in a database, It is also used with SAVEPOINT command to jump to a savepoint in an ongoing transaction.

Constraints in SQL
====================

Constraints in SQL means we are applying certain conditions or restrictions on the database.
By using constraints we can apply some conditions and restrictions on database. 

Constraints available in SQL are:
 
• NOT NULL
• UNIQUE
• PRIMARY KEY
• FOREIGN KEY
• CHECK
• DEFAULT

1. NOT NULL
 -----------
• NULL means empty, i.e., the value is not available.
• Whenever a table's column is declared as NOT NULL, then the value for that column cannot be empty for any of the table's records.
• There must exist a value in the column to which the NOT NULL constraint is applied 
 
CREATE TABLE Student (
  id INT,
  name VARCHAR(50) NOT NULL
);

• UNIQUE
  -----------

• Duplicate values are not allowed in the columns to which the UNIQUE constraint is applied.
• The column with the unique constraint will always contain a unique value.
• Using the UNIQUE constraint, you can also modify the already created tables.
CREATE TABLE User (
  email VARCHAR(100) UNIQUE
);


3. PRIMARY KEY
  -----------

• PRIMARY KEY Constraint is a combination of NOT NULL and Unique constraints.
• NOT NULL constraint and a UNIQUE constraint together forms a PRIMARY constraint.
• The column to which we have applied the primary constraint will always contain a unique value and will not allow null values.
• Example : students id teachers id this type of examples are primary key.

CREATE TABLE Employee (
  emp_id INT PRIMARY KEY,
  emp_name VARCHAR(50)
);

  -----------

• When we have two tables, and one table takes reference from another table, i.e., the same column is present in both the tables and that column acts as a primary key in one table. That particular column will act as a foreign key in another table.

SQL | Subquery
======================
A Subquery is a query within another SQL query and embedded within the WHERE clause.
• A subquery is enclosed in parentheses.
• A subquery is a query within another query. The outer query is known as the main query, and the inner query is known as a subquery.
• In the Subquery, ORDER BY command cannot be used. But GROUP BY command can be used to perform the same function as ORDER BY command.
 
• A subquery can be placed in a number of SQL clauses like WHERE clause, FROM clause, HAVING clause.
• You can use Subquery with SELECT, UPDATE, INSERT, DELETE statements along with the operators like =, <, >, >=, <=, IN, BETWEEN, etc

If the inner query DOES NOT use outer query columns Non-Correlated Subquery

If the inner query USES outer query columns Correlated Subquery

ACID properties are database rules to handle transactions safely.

They make sure data is not lost or corrupted during a transaction.



ACID stands for:

1. Atomicity
2. Consistency
3. Isolation
4. Durability

---

## 1️⃣ Atomicity

**Atomicity means all or nothing.**

If a transaction has multiple steps and **any one step fails**, then **all changes are rolled back**.

**Example:**
While placing an order, if payment fails, then order creation and stock reduction are also cancelled.

So, a failed transaction is **never partially saved**.

---

## 2️⃣ Consistency

**Consistency means data rules must be correct before and after the transaction.**

**Example:**
In a bank transfer, total money before and after transfer remains the same.
No business rule should be broken.

So, the database always moves from **one valid state to another valid state**.

---

## 3️⃣ Isolation

**Isolation means multiple transactions do not affect each other.**

**Example:**
If two users try to buy the last product at the same time, only one transaction is allowed only one allow to buy a product to one user.
The other transaction waits or fails.

order canceled after 15 min at that time we refund the customer amount

So, users do not see incomplete or wrong data.

---

## 4️⃣ Durability

**Durability means once a transaction is committed, data is permanently saved.**

**Example:**
After payment success, even if the server crashes, order and payment data are not lost.

Data remains safe in the database.

---

## 🎤 Final One-Paragraph Answer (Very Important)

> “ACID properties ensure reliable database transactions. Atomicity ensures rollback if any step fails, Consistency maintains business rules, Isolation handles multiple users safely, and Durability guarantees data is permanently saved after commit.”

What is Views in SQL.
==========================
Views in SQL (Simple Explanation)
A view is a virtual table because it doesn’t store data directly like normal tables. It just stores a query. When you use (execute) the view, it runs the query and shows data from the real tables.


Why views are useful:
Simplify complex queries – Instead of writing long queries with multiple tables every time, you can create a view once and just use it.
Example: Instead of joining Students, Courses, and Enrollments every time, create a view called StudentCourseView and then do:
SELECT * FROM StudentCourseView;

**Hide complexity – Users don’t need to know how many tables exist or how they are connected. The view gives a simple interface to see data.

**Improve security – You can show only specific columns to users.
Example: Show only student names and departments, hide phone numbers or salaries.

**Reusability – Once a view is created, you can use it in different reports or modules without writing the same query again.

Consistency – Everyone using the view sees the same data and logic, which reduces mistakes.

Materialized views (optional) – Some views can store the result of the query. This makes heavy queries faster because the data is precomputed.

Updatable views – In some cases, you can insert, update, or delete data through a view. The changes go to the original table, not the view itself.

Summary:
Views make complex queries simple
Hide table structure from users
Improve security by showing only required data
Can be reused across reports
Keep data consistent
Sometimes improve performance
We can also make joins on resulted view data

UseCases:
**Used heavily in reporting and analytics.
**Can be reused across multiple reports and dashboards screens.
Create views to combine multiple tables (like Orders, Customers, Products) into one virtual table.
Analysts and BI tools query the view instead of writing complex joins.

In short: Views make working with databases easier, safer, and cleaner.

## map(), filter(), and reduce() in JavaScript (Simple English)

In JavaScript, **map()**, **filter()**, and **reduce()** are array methods.

## 1. map() Method

**What is map()?**	

map() is used when we want to change every element in an array and get a new array.
.

* It goes through every element
* It changes the value
* It returns a new array

### Example

```javascript
let arr = [2, 4, 8, 10];
```

**Output**

The `filter()` method is used to **select elements** from an array based on a **condition**.

### Example

```javascript
let arr = [2, 4, 8, 10];
let updatedArr = arr.filter(val => val < 5);

console.log(arr);
console.log(updatedArr);
```

**Output**

```
[2, 4, 8, 10]
[2, 4]
```


---

## 3. reduce() Method

**What is reduce()?**

reduce() is used to combine all array values into one single value.

* It adds, subtracts, multiplies, or combines values
* Final result is one value, not an array

### Correct Example (Sum of all numbers)

```javascript
let arr = [2, 4, 8, 10];
let result = arr.reduce((total, curr) => total + curr, 0);

console.log(arr);
console.log(result);
```

**Output**

```
[2, 4, 8, 10]
24
```

============= 
--> In JavaScript, this is a keyword that refers to the object which is currently calling the function. 
-->In the case of classes, it points to the current instance of the class.
-->this not same as like other languages Its value is decided at runtime based and it depends on how a function is called, not where the function is written**.

In simple words:

> **`this` = “who called me?”**

function showName() {
  console.log(this.name);
}

const user1 = { name: "Aziz" };
const user2 = { name: "Khan" };

showName.call(user1); // Aziz
showName.call(user2); // Khan

--------------------------

### Why do we need `this`?
--------------------------

--> We need `this` to make our functions reusable and dynamic.
--> Instead of hard-coding values, `this` allows the same function to work with different objects.

In real applications, we use `this` to access:

* the current object’s properties
* the current class instance
* the current component or service state

Imagine you write **one function** and want to reuse it for **many objects**.

Without `this` ❌:


function printName() {
  console.log(user1.name);
}

With `this` ✅:


function printName() {
  console.log(this.name);
}

Now:

* Same function
* Works for many objects
* Cleaner, scalable code

👉 **This is why `this` exists.**
-----------------------------

### `this` in different scenarios
-------------------------------------

**Global scope:**
-------------------------------------
In the browser, `this` refers to the `window` object.

Ex : 

console.log(this);

### In browser:

window

📌 Reason:

* No caller
* JS uses global object

# 4️⃣ `this` Inside a Normal Function

function test() {
  console.log(this);
}
test();

### Output (non-strict mode):

window

📌 Why?

* Function is called normally
* Default caller = global object

**Inside a normal function:**
-------------------------------------
If a function is called normally, `this` refers to the global object.
In strict mode, it becomes `undefined`.

 `this` in Strict Mode (This Substitution)

"use strict";

function test() {
  console.log(this);
}
test();


### Output:

undefined

📌 Why?

* Strict mode **does not allow automatic `window` binding**
* Prevents bugs

👉 Interview line:

> “In strict mode, `this` inside a function becomes `undefined`.”

---
 `this` Depends on HOW It Is Called

Same function, different calls 👇

function show() {
  console.log(this);
}

show();

➡ `this` = `window`

const obj = { show };
obj.show();

➡ `this` = `obj`

🔥 SAME function
🔥 DIFFERENT `this`

This proves the golden rule.

---



**Inside an object method:**
-------------------------------------
When a function is called as an object method, `this` refers to that object.

const user = {
  name: "Ajmal",
  greet() {
    console.log(this.name);
  }
};

user.greet();

### Output:

Ajmal


📌 Why?

* Method is called using `user`
* So `this` = `user`


**How it is called matters:**
-------------------------------------
The same function can have different `this` values based on how it is invoked.

**call, apply, and bind:**
-------------------------------------
These methods are used to explicitly set the value of `this`.
They are commonly used for method sharing and fixing `this` in callbacks.


* Reuse same function
* Control `this`
* Very common in real projects


**Arrow functions:**
-------------------------------------
-->Arrow functions do not have their own `this`.
-->They inherit `this` from their surrounding scope, which is called lexical `this`.

-->Normal functions decide this at call time. Arrow functions take this from where they are written.

⚠️ Arrow functions **do NOT have their own `this`**.

const obj = {
  name: "Ajmal",
  greet: () => {
    console.log(this.name);
  }
};

obj.greet();


### Output:

undefined

📌 Why?

* Arrow function takes `this` from **parent scope**
* Parent scope = global

---


**Nested arrow functions:**
-------------------------------------
A nested arrow function continues to use the `this` value from its parent function.

`this` Inside Nested Arrow Function (IMPORTANT)

const obj = {
  name: "Ajmal",
  greet() {
    const inner = () => {
      console.log(this.name);
    };
    inner();
  }
};

obj.greet();


### Output:

Ajmal


📌 Why?

* `greet()` has `this = obj`
* Arrow function **inherits it**

🔥 This is the correct use of arrow functions.


**DOM events:**
-------------------------------------

In a normal event handler function, `this` refers to the DOM element that triggered the event.
In an arrow function, `this` refers to the outer scope instead of the element.

### Normal function (GOOD)

button.addEventListener("click", function () {
  console.log(this);
});

➡ `this` = button element

### Arrow function (NOT GOOD)

button.addEventListener("click", () => {
  console.log(this);
});

➡ `this` = `window`

📌 Why?

* Arrow ignores event binding




path.join()?:

## 1️⃣ What is `path.join()`? (Simple English)

> **`path.join()` safely combines multiple path parts into one valid file path.**


## 2️⃣ Why do we NEED `path.join()`?

Different operating systems use **different path separators**:

| OS            | Separator |
| ------------- | --------- |
| Windows       | `\`       |
| Linux / macOS | `/`       |

If you hardcode paths, your code may **work on your laptop** but **fail in production**.

---

## 3️⃣ What `path.join()` ACTUALLY DOES (Important)

When you write:

path.join(__dirname, "../uploads")

Node does **ALL of this automatically**:

### ✅ 1. Uses correct separator

* Windows → `\`
* Linux → `/`

### ✅ 2. Removes extra slashes

```js
path.join("a//", "//b") → "a/b"
```

### ✅ 3. Resolves `..` (go up)

```js
path.join("a/b", "../c") → "a/c"
```

### ✅ 4. Resolves `.` (current folder)

```js
path.join("a/b", "./c") → "a/b/c"
```

### ✅ 5. Returns a CLEAN, ABSOLUTE path (when base is absolute)
